- `example-001.md`、`task-mumqn14s.md` 是 git 追蹤的,用 `git restore` 完整復原。
- `task-mumqmk58.md` 從未進過 git,靠協調者(我)對話一開始讀過的原始內容手動重建(標題「開發」、backlog、agent: claude、內容全空)。**這張檔案的重建無法用 git diff 100% 驗證位元對位元一致**,只能保證跟我記錄的原始內容一致。
- 之後派工(用量估算 subagent)時已在 prompt 裡加了強制規則:只能刪明確檔名、清理前後要列目錄清單比對,該次驗證乾淨,沒有再發生。

**教訓**:之後任何會叫 subagent 在 `board/tasks/` 或其他共用資料夾建立測試資料再清理的任務,delegation prompt 都要內建「只刪明確檔名、清理前後 diff 目錄清單」這兩條,不能只靠一般性的「不要動別人的任務」提醒。
