1. **codex 0.157 已移除 `--full-auto`**:原 `agents.json` 的 codex 派工從那時起全部失敗。已改為 `exec -s workspace-write`(commit `301386e`)。

4. **核心機制已用真實 claude 驗證**:單一 pipeline 跑「計畫 → 停在待核准 → 你核准 → 執行」,計畫 artifact 內容完整,核准前不會動檔,核准後 `hello.txt` 被正確修改。

## 四、你回來後的測試方案(照順序,約 15 分鐘)
**前置**:`node tools/server.mjs`(若已在跑且是 2026-09-30 之後啟動的就不用重啟),開 `http://localhost:4173`,`npm test` 應 56+ 全過。

1. **畫面**:重新整理,確認卡片不再被長 `files` 撐爆、五欄看板可正常看。
2. **Project**:按「📂 專案」新增一個 project,路徑指向一個「可拋棄的測試資料夾」(建議先 `git init` 一個空 repo)。故意填不存在的路徑,應被擋下。
3. **新任務**:按新增,選該 project,填目標與驗收條件,pipeline 選 `single`(或 `standard`)。舊的「未綁定專案」任務應顯示警告。
4. **計畫關卡(最重要)**:派工 → 任務進入「需要你處理」前,呼叫 `GET /api/runs/<任務id>` 與 `/artifacts/plan.md` 看計畫(目前 UI 尚無核准按鈕,WP4 才做;暫用 API:`POST /api/runs/<id>/approve` 或 `/reject` 帶 `{"feedback":"..."}`)。驗證:**核准前測試資料夾內沒有任何檔案被改動**。
5. **退回**:對計畫 `reject` 並附意見,確認重新產生的計畫有回應你的意見。
6. **停止**:執行中呼叫 `POST /api/runs/<id>/stop`,確認行程被砍(工作管理員裡沒有殘留 claude/codex)。
7. **回修迴圈**(可選,耗額度較多):用 `standard` pipeline 讓 codex 實作、claude review,觀察 review FAIL → revise → 最多 3 次後停在 needs-you。
8. **舊派工相容**:建一張沒有 project/pipeline 的任務,派給 codex-a,確認仍可跑、log viewer 有輸出(此路徑現在才修好 codex 旗標)。
9. **agy**:`agy --mode plan --output-format stream-json -p='只回 OK'` 手動確認你的 agy 登入狀態正常。

驗收標準:第 4 步「核准前不動檔」不可有例外;第 6 步不可有殘留行程。
