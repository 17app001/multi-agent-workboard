# Multi-Agent Workboard 使用手冊

給「一個人同時用多個 AI 編碼 agent」的本機任務控制中心。核心承諾:**agent 先出計畫,你核准後才會動手改檔**;你按下「派工」就可以離開,回來時一眼看出誰做到哪、有沒有卡住、要不要你處理。

## 1. 啟動
```
node tools/server.mjs            # 預設 http://localhost:4173(只綁本機 127.0.0.1)
npm test                         # 單元/整合測試(不呼叫真實 CLI)
npm run test:e2e                 # 真實 Chrome/Edge 的瀏覽器測試(找不到瀏覽器會自動 skip)
```
改了 `tools/` 要重啟 server;改 `web/` 重新整理即可。

## 2. 一分鐘上手(日常流程)
1. **專案**(右上「📂 專案」):新增你要 agent 工作的資料夾(id、名稱、絕對路徑)。可選填「測試指令」(例如 `pytest`),以及「用 git worktree 隔離」(見 §6)。
2. **新任務**(「+ 新任務」):填標題、目標、驗收條件;選 agent、專案、**流程**。
3. **派工**(任務卡上的「▶ 派工」):agent 先在**唯讀模式**產出計畫。
4. **核准**:任務出現在首頁最上方紅框「需要你處理」。點「立即審查/處理」進入詳情頁,讀計畫:
   - **核准並繼續**:才會開始施工(這是唯一能讓 agent 改檔的入口,沒有任何旁路)。
   - **退回並附意見**(必填):agent 會依意見重出計畫。
5. 施工完成後(依流程可能再跑測試、Claude 審查、自動回修),任務變成「已完成」。
6. 收工時按「收工」:預覽當日工作日誌與交接檔更新,確認後才寫檔(只寫新檔或 `<!-- AUTO:BEGIN/END -->` 區塊)。

## 3. 畫面
- **控制中心**(首頁):左=各 agent 狀態、用量、codex 額度;中=任務分頁(需要你處理 / 執行中 / 排隊中 / 已完成);右=最近活動。完成超過 3 天的卡片預設收起。
- **看板視圖**:傳統五欄,可拖曳。
- **用量統計**:今日/近 7 天/本月(只計「透過看板派工」的任務)、各 agent 分佈、最耗資源的任務。首頁的「今日用量」則是本機所有 CLI 的全部使用量。費用一律是 **API 等值估算,非實際扣費**。
- **任務詳情**:流程進度(每步的 agent/模型/用量/耗時)、即時事件、產出成品(計畫、審查、測試輸出、diff)、原始輸出、對應的操作按鈕。
- **開工**:10 行內簡報(上次做了什麼、各狀態任務、待決事項)。

## 4. 流程(pipeline)
| 流程 | 內容 |
|---|---|
| `single`(預設) | agent 出計畫 →(你核准)→ 同一個 agent 施工 |
| `standard` | Claude 出計畫 →(你核准)→ **codex 池施工**(某帳號額度用完會自動換下一個)→ 跑專案測試 → Claude 審查(首行 `VERDICT: PASS/FAIL`)→ 不過則回修(最多 3 輪,超過交還給你) |
| `decompose` | 「🧩 需求拆解」專用:丟一句大需求,規劃者拆成多張任務卡草案,你編輯確認後才建卡 |

任務沒選流程時,用專案的預設流程;都沒有就用 `single`。**所有流程在任何施工步驟之前都必定有計畫核准關卡**,驗證器強制,沒有關閉選項。

「測試」步驟的指令取專案的 `testCommand`;沒設定但專案有 `npm test` 就跑 `npm test`;都沒有就略過(不會失敗)。

## 5. Agent 與額度
設定在 `agents.json`(`agents`、`pools`、各自的 `models`/`defaultModel`)。
- **codex-a**(`~/.codex`)、**codex-b**(Mika,`~/codex-agents/mika`):同一個 pool `codex`,順序 codex-b 優先。額度資訊(5 小時/每週已用 %、幾點重置)直接取自 codex 自己的 session log,顯示在首頁;快滿(預設 ≥90%)會提前換人;資料超過 6 小時標示「資料可能過期」,不會據此擋派工。
- **claude**:額度沒有本機可讀來源,看板不顯示。
- **agy**(Antigravity CLI):見下。**gemini** CLI 帳號已不可用。
- 模型:每個 agent 可在新任務表單選模型;不選就用該 agent 的預設。

### agy 要先開權限
agy 在無人值守(headless)模式下沒有權限設定時,會自動拒絕所有指令、什麼都不做。要讓它施工,**由你自己**在終端機執行:
```
node tools/agy-permissions.mjs on       # 備份設定並開啟(全域,所有 agy 視窗都生效)
node tools/agy-permissions.mjs off      # 用完立刻還原
node tools/agy-permissions.mjs status
```
沒開時,任務會停在「需要權限」並告訴你怎麼做,不會默默失敗。

## 6. git worktree 隔離(多個 agent 同時開發不互踩)
專案勾選「用 git worktree 隔離」後,每個任務在獨立分支(`agent/<任務id>`)的獨立目錄施工。完成後詳情頁出現:
- **合併到專案**:會檢查專案主目錄沒有未提交修改、主分支在這段期間沒被改動;任何不符就**不合併**,分支保留。
- **丟棄變更**:移除分支與目錄(不可復原)。
專案必須是 git repo;無法建立 worktree 時任務會拒絕啟動,**不會退回在主目錄施工**。

## 7. 疑難排解
| 現象 | 原因 / 做法 |
|---|---|
| 首頁要等很久才有資料 | 用量/分析要掃很多 log,已改為背景計算、先顯示任務;第一次開啟 server 後稍等數秒 |
| 任務停在「需要權限」 | agy 沒開權限,見 §5;或改派給 codex |
| codex 回「usage limit」 | 額度用完;若用 `standard` 流程會自動換下一個帳號;全部用完會停在「需要你處理」並列出各自重置時間 |
| 用量「無資料」 | 該 step 的 CLI 輸出沒有用量,或 agent 沒有解析器 |
| 操作被回 403/415 | 只接受 `localhost:4173` 的同源 JSON 請求(防 CSRF);請用瀏覽器頁面操作,不要從別的網站或 LAN 存取 |

## 8. 安全與限制
- server 只綁 127.0.0.1;所有會改變狀態的請求都驗證 Host/Origin/JSON。**不要對外公開**。
- 任何 agent 不會收到 `--dangerously-*` 類旗標。
- 專案的 `testCommand` 會以 shell 執行——它跟你的專案設定同等信任,請只填自己寫的指令。
- 目前沒有自動化測試涵蓋的部分:通知(瀏覽器通知需你手動允許)、需求拆解畫面的編輯流程、回修迴圈介面的按鈕細節。
